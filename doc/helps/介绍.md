# Element Plus 也能「无界」：开源后台 sleveen-admin 首次亮相

> 作品声明：个人观点、仅供参考  
> 提示：项目仍在迭代打磨，部分能力准可用；可作底座与二次开发起点，上生产前请自行评估。  
> 姊妹篇：流程引擎 [SailFlow](https://www.toutiao.com/article/7703839769515557419/)（可插拔中国式 OA 内核）已在本仓同仓挂载。

---

开源后台管理系统，并不缺。

缺的是：习惯 **Element Plus** 的团队，也能拿到高颜值壳；菜单与内容不再「三层下巴」割裂；门户、审批、业务模块不是后期硬贴，而是底座上长出来的。

我把这套东西叫 **sleveen-admin**——**Element Plus 版 Soybean + .NET 10** 的现代化后台。功能蓝本对齐 Admin.NET，ORM 走自研 **mooSQL**；前端深度改造成 Element 壳；同仓集成工作流 **sailflow** 与自研 **vue-bpmn**，OA 与上层业务开箱可搭。

一句话定位：

> **不是又一个 CRUD 脚手架，而是「好看壳 + 纯净核 + 可插拔业务」的平台底座。**

---

## 为什么还要再做一个 Admin？

做后台的朋友大概都踩过这几类坑：

- 想用 Element，壳却是 Naive / Ant Design 原版，团队组件库两套心智；
- 布局只有「左菜单 + 顶栏 + 灰底内容」，页签一多，画面又挤又碎；
- 门户首页是写死的卡片 Demo，千人千面要另起工程；
- 审批流外挂一套黑盒，设计器改不动，选人规则改一次炸一次；
- 业务模块没有范式，人与 AI 一起堆代码，三个月后谁都不敢动。

sleveen-admin 的赌注，就是把这些痛点收进**同一套底座**：壳要好看、核要干净、扩展有固定落点、流程与门户不是外挂。

---

## 九大特色（真正想让人记住的）

### 1. Element Plus × Soybean × .NET 10

面向习惯 **Element** 生态的团队：前端不是 Naive 原版 Soybean，而是 **Element Plus 深度改造壳**；后端全量 **.NET 10**。

- 保留 `@sa/*` 物料体系（hooks / axios / materials），壳层与主题抽屉按 Element 深度重做；
- 功能蓝本对齐 Admin.NET（认证、RBAC、租户、基础设施），ORM 用自研 **mooSQL**，不绑 Furion / SqlSugar 心智。

**Element 熟练度可直接复用**，同时吃到 Soybean 级壳体验与现代 .NET 宿主。

---

### 2. 高达 9 种布局模式

一套主题配置切换，不必另起壳工程：

| 模式 | 观感 |
|------|------|
| 左侧 / 左侧混合 / 顶部 / 各类混合 | 常规后台全覆盖 |
| **左栏无界**（默认） | 圆角卡片侧栏 + 内容整页 |
| **顶栏无界** | 毛玻璃浮岛顶栏 |
| **底部无界** | 底部停靠栏沉浸式 |

从经典左栏到沉浸式工作台，主题抽屉一键切。默认就是「左栏无界」——不是演示开关，是日常开箱体验。

---

### 3. 特色【无界】模式（最想被记住的）

传统 Admin 常是：**菜单栏 · 页签栏 · 内容栏** 三层下巴叠出臃肿感。无界要做的事很简单——

**让菜单与内容同一画幅，业务页可以沉浸铺满。**

两套正交能力：

1. **布局级无界**（左栏 / 顶栏 / 底部卡片）：侧栏或顶栏以圆角卡片、毛玻璃浮岛呈现，内容区整页展示，氛围底铺满。
2. **页面级无界**（菜单类型「无界 Vue」）：压缩顶栏与页签、侧栏悬浮、内容去掉多余外边距，背景可全屏穿透。

首页典型组合：

```text
左栏无界布局
  + 无界 Vue 页
  + 门户引擎 paotal
```

业务模块只要把菜单类型设为无界 Vue，就能直接吃到沉浸一体观感——不是首页特供皮肤。

---

### 4. 内置门户：设计器 + 千人千面

门户不是演示页，而是可配置工作台：

- 门户方案 / 页面 / 组件库 / 可视化设计器；
- 运行时引擎 `paotal`：卡片网格、Portlet、图表与多播部件；
- **千人千面准可用**：个人门户优先 → 组织 / 公开兜底，首页与业务子门户同一套解析链。

无界壳 + 门户装配，首页不再是「欢迎使用本系统」空壳，而是真正的工作台入口。

---

### 5. 同仓挂载 sailflow：中国式 OA 开箱可搭

流程引擎不以「外挂黑盒」方式塞进来：

- 运行语义在独立仓 **sailflow**（MIT，可插拔，专治中国式审批）；
- 本仓做 **Host 薄适配 + 前端工作台** 同仓交付。

覆盖面包括：待办 / 已办 / 抄送、发起与办理台、BPMN 设计（`sf:` 扩展）、动态表单、规则集 · AI 活动 · 知识库、Outbox 死信、分类与报表……

办理动词走引擎命令（通过、驳回、退回、加签、重发、转办……），选人走待办人管道，事件走 Gate / Hook / Notifier——和 SailFlow 首篇介绍的那套扩展哲学一致，只是这次**壳与工作台都在眼前**。

---

### 6. 源码集成自研 vue-bpmn

设计器不止绑死 `bpmn-js`：同仓源码集成自研 **vue-bpmn**，符合 BPMN，改扩建不受第三方黑盒约束。

需要改选区、属性面板、XML 进出或 `sf:` 扩展时，**直接改本仓库源码**，不必 fork 上游 npm 包。统一工具栏还可在 `bpmn-js` / `vue-bpmn` 间切换心智，产品面不被单一家绑架。

---

### 7. 完善规范文档：给人看，也给 AI 用

在 AI 辅助写业务的时代，**缺文档 = 堆泥球**。

sleveen-admin 把文档当成驱动契约，而不是附录：

- Biz / VC / Page 业务模块范式（前后端同构命名）；
- vclist 列表查询管道（条件、排序、表格/卡片双视图）；
- 无界、门户、子工作台实施路径；
- SQL 安全与审计红线；
- sailflow 菜单挂载、按钮、字段模式、表单生命周期……

按范式在 `widgets/<域>/` 与后端 Biz 栈落文件，再挂菜单，即可稳定扩展。Cursor 规则与文档交叉索引，约束 Agent 改码落点——**适合「人 + AI」长期堆业务**。

---

### 8. 多数据库适配无痕

开发默认 **SQLite**：`dotnet run` 自动建目录、建表、Seed，零外部库依赖即可起全站。

切 SQL Server / 其他方言：改连接配置即可；Hangfire 随主库走 Hangfire.MooSql；业务继续用 Repository / SQLBuilder，**不为方言分叉业务代码**。流程库还可与主库分置。

---

### 9. 纯净核心：瘦核 + 厚扩展

刻意保持「系统只留最核心能力」：

- 后端：`Foundation`（基础设施）+ `System`（认证 / RBAC / 组织 / 字典…）+ `Web.Api` 宿主；门户、AI、流程 Host、行业域以独立包 / widgets 生长；
- 前端：`layouts` / `ui` 为壳，业务进 `widgets/sailflow`、`officeman`、`portaldesign`……

禁止 Java 式 `IUserService` / `UserServiceImpl` 堆叠；业务 Service 用具体类 + 源生成 DI。新域推荐路径清晰：**后端切片 + 前端 widgets → Seed / 菜单挂载**，核心仓不肥。

## 技术栈速览

| 层 | 选型 |
|----|------|
| 后端 | .NET 10 · mooSQL · JWT · Hangfire.MooSql · YARP · Redis（可选） |
| 前端 | Vue 3 · Vite 7 · Element Plus · UnoCSS · 门户引擎 · vue-bpmn |
| 流程 | sailflow（独立仓）+ 本仓 Host / 工作台 |
| 部署 | 开发双进程或 Unified 单端口；生产 SPA + Docker 单端口 |

平台能力还包括：RefreshToken、按钮级权限、多租户、站内信、SignalR 在线用户、操作/访问日志、服务器与 Redis 监控、MAF 流式 AI 助手等——该有的底座都在，**特色却不靠功能清单凑数**。

## 适合谁？不适合谁？

**适合**

- .NET + Vue 团队，想要 Element 生态下的高颜值后台底座；
- 需要门户工作台、业务子门户、沉浸式「无界」观感；
- 要同仓搭中国式 OA（审批 + 设计器 + 办理台），而不是另买一套；
- 希望业务模块有范式，方便人和 AI 一起长期堆叠。

**暂时不适合**

- 只要一个「十分钟生成 CRUD」的极简模板，不关心壳与扩展纪律；
- 无法接受迭代期打磨、直接当生产 SaaS 零配置上线。

---

## 写在最后

开源 Admin 不缺「功能很多」。

真正稀缺的是：**壳有辨识度、核够干净、扩展有契约、流程与门户不是临时贴片。**

sleveen-admin 想赌的几件事：

1. **无界**——菜单与内容一体，氛围感拉满；  
2. **门户**——千人千面工作台，不是首页 Demo；  
3. **sailflow + vue-bpmn**——中国式 OA 同仓可改；  
4. **Biz/VC 范式 + 文档**——人与 AI 都能按图施工；  
5. **纯净核心**——业务以插件生长，底座不肥。

若你也在 Element + .NET 栈里跟后台、门户、审批死磕，欢迎来仓库看 README 九大特色与 `doc/` 规范，提 Issue、PR 一起打磨。

姊妹项目 SailFlow（流程内核）已发过介绍；本篇是**宿主壳与产品面的第一次正式亮相**——壳立住了，业务才能扬帆。
