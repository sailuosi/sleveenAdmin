## 1. SQL 安全与 mooSQL 写法

> **专篇（强制、含正反例与问题 Demo）** → [**SQL安全审计要求.md**](./SQL安全审计要求.md)  
> 日常开发摘要见风格 §2.4–§2.5。本节只保留索引级摘要，**细则以专篇为准**。

| 等级 | 一句话 |
|------|--------|
| **P0** | 外部输入拼进 SQL → 立刻改参数化 |
| **P1** | 运行时值进 `exe*`/`Format` 整段 SQL → 禁止新增 |
| **P2** | `SqlFilter`/手工转义后再拼 → 新代码禁止 |
| **P3** | 动态表/列/排序 → 须白名单 |
| **红线** | 躲扫描（中间变量骗门禁）→ 违纪 |

Guid 相等用 **`whereGuid`**；限行 `.top`；软删 `whereIsOrNull`；行数 `.count()`；「现在」`DateTime.Now`。

## 2. DataRow 读取

**依据**：风格 §2.3。

| 等级 | 问题 | 要求 |
|------|------|------|
| **P0** | `getXxx(key, default) ?? default` 二次缺省 | 删除尾部 `??`（第 2 参已是缺省） |
| **P1** | `row["col"].ToString()` / 手写 `DBNull` / `Convert.To*` | 改 `getString` / `getInt` / `getDateTime` / `getGuid` 等 |
| **P2** | `(T)row["col"]` 强转 | 改对应 `get*` |
| — | `set` 接受 `DataRow` 单元格 | 一般不必再包一层 `getString` 仅为 set（风格 §2.5） |

**不计违规**：非 DataRow 的 DTO 取值；跨列回退 `getString(A,"") ?? getString(B,"")`。

```csharp
// ✅
var status = row.getString("En_Status", "");
var oid = row.getGuid("Sa_EbNoteOID");

// ❌
var status = row.getString("En_Status", "") ?? "";
var v = row["En_Title"] == DBNull.Value ? "" : row["En_Title"].ToString();
```

## 3. 主键 / 外键 Guid 强类型

**依据**：风格 §3 + [数据库查询.md](../design/数据库查询.md)。

| 等级 | 问题 | 要求 |
|------|------|------|
| **P0** | OID/FK 用 `'"+oid+"'` 拼进 SQL | 立刻 `whereGuid` / `whereFormat` 参数化 |
| **P1** | 实体已是 `Guid?` 仍 `getString("…OID/_FK")` 或 `TryParse(getString)` | 改 `getGuid`；无效时 `!HasValue \|\| == Guid.Empty` 早退 |
| **P2** | 业务链路长期 `string xxxOid/Fk`；`where`/`set` 无谓 `ToString()` | API 边界可 string；进业务立刻 `TryParse`→`Guid?`；set/where 直接传 Guid |

**例外（可保留 string）**：列本身是字符串承载的 Guid 文本（处所注明）；`DataTable.Select` 临时 `"D"`；非 OID 编码字段；实体仍声明为 `string` 的列不要强改。

## 4. 接口入参

**依据**：风格 §4。

| 等级 | 问题 | 要求 |
|------|------|------|
| **P1** | 扁平/近扁平 Body 用 `[FromBody] JObject` | 改专用 DTO；列表用 `BizQueryInput` |
| **P2** | `para["key"]?.ToString()` / `para.Value<T>` | 改 DTO 属性或强类型取值 |
| **P3** | 已有 DTO 仍残留索引取值 | 触达收口 |

**例外**：深层嵌套需 `JToken` 游走 → 可保留 `JObject`/`JToken`/`JArray`，**处所注明原因**。  
**不约束**：返回值经 `ApiResult` / `Ok(...)`。  
固定形状入参优先专用 DTO。

## 5. 禁用 dynamic / 覆盖区 / 大表 Join（规范审计项）

虽非独立审计报告主题，评审同等适用：

| 主题 | 要求 | 依据 |
|------|------|------|
| **dynamic** | 禁止参数/局部/字段/返回值使用 `dynamic`；触达改为静态类型 | 风格 §5 |
| **覆盖区** | Entity/Biz 禁止污染 `[cover]`；VC/Page 须改则 `[cover-break][已改]` 或整段删除 | 风格 §7、生成规范 |
| **大表 Join** | 列表/导出主查询禁止 Join 或相关子查询扫大表；附属展示前端按当前页补数 | 风格 §2.6 |

## 6. 删除：逻辑删除 vs 物理删除

### 6.1 判定

| 形态 | 类型 |
|------|------|
| `doDelete` / `DELETE FROM` / 实体 `Remove()` | **物理删除** |
| `set("SYS_Deleted", true\|1).doUpdate` / `BizServiceBase.RemoveByOIDs` | **逻辑删除** |
| region 注释写「逻辑删除」但实现仍物理删 | **按物理计**（以执行为准） |
| 空的「逻辑删除」`#region` | **不代表**软删，不得据空 region 下结论 |

### 6.2 要求

| 项 | 要求 |
|----|------|
| **新接口策略** | 需可恢复、或仍被外键引用的主数据：**优先逻辑删除**，并保证列表/计数查询带 `whereIsOrNull("SYS_Deleted", 0)` |
| **物理删除** | 仅当业务明确需要时使用，并在接口/Service **注释写清「物理删除」原因** |
| **双路径** | 同一张表若同时存在 soft/hard：入口参数或方法名须区分，文档与注释写清默认值 |
| **禁止误导** | 不得保留空的「逻辑删除」region 冒充软删 |
| **一致性** | 同表多入口软硬不一视为债；触达治理时按表统一策略 |

### 6.3 评审检查点

- [ ] 删除入口是物理还是逻辑？与产品预期是否一致？  
- [ ] 若逻辑删：查询侧是否过滤 `SYS_Deleted`？  
- [ ] 若物理删：原因是否注释？关联子表是否一并约定？  
- [ ] 是否存在「注释软、实现硬」或空 region 误导？

## 8. 评审速查清单

新增或改动后端接口 / Biz 时，按序勾选：

**SQL / mooSQL**

- [ ] 无拼接注入；无躲扫描  
- [ ] Guid 用 `whereGuid` / `getGuid` / `Guid?`  
- [ ] 限行 `.top`；软删过滤 `whereIsOrNull`  
- [ ] `set` 时间用 `DateTime.Now`；无谓 `ToString`  
- [ ] 纯行数用 `.count()`  

**入参 / 读取**

- [ ] 列表 → `BizQueryInput`；其它固定形状 → 专用 DTO  
- [ ] DataRow → `get*`；无二次 `??`  
- [ ] 无新增 `dynamic`  

**删除 / 结构**

- [ ] 删除语义明确（软/硬）；列表过滤与之一致  
- [ ] 未污染 Entity/Biz `[cover]`；列表无大表 Join  

**生成**

- [ ] 个性化在覆盖区外，或 VC/Page 已打 `[cover-break]`
