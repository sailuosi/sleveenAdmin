## 2. 多库与 mooSQL

### 2.1 多库连接位

本项目后端可对接**多个数据库**。凡执行数据库操作的业务逻辑，须先确认连接位（`position` / DB 实例，默认见 `MooSqlSetup.DefaultPosition`），谨防写错库。

### 2.2 一律使用 mooSQL，按场景选型

| 场景 | 方式 |
|------|------|
| 无表实体类 | `SQLBuilder` |
| 快速查询单个实体一行全部列 | 仓储，或 `SQLBuilder` 快捷实体扩展方法 |
| 取部分列 + 复杂条件 + 复用语句片段 | `SQLBuilder`（可用 `record` / `useApart`） |
| 简单条件快捷查询实体列表 | `SQLClip` |
| 大批量插入 | `BulkTable` 或 `BatchSQL` |
| 按条件灵活更新、删除 | `SQLBuilder` |
| 标准 Biz 分页 CRUD | `BizServiceBase` + `Db.useSQL()`（见范式文档） |

### 2.3 结果读取

- 查询得到 `DataTable` 后，对行取列的强类型值，应使用 mooSQL 的 **`DataRow` 扩展**系列方法，避免自行多重判空转换。
- 查询结果为实体时，优先使用 `SQLBuilder` 的 **`query<T>()`**；实体有特性或属性名与字段一致即可映射，避免冗余手工转换。
- `getString` / `getInt` 等带第 2 参数的重载，**第 2 参数即为缺省值**；勿再叠一层 `??` 缺省。
- kit / 查询结果须为静态类型（见 **§5 禁用 dynamic**）；否则 DataRow 扩展会在运行期绑定失败。
- 主键 / 外键列取值与传参见 **§3**（优先 `getGuid` / `Guid?`）。

```csharp
// ❌ 第 2 参数已是缺省值，二次 ?? 冗余
var type = row.getString("En_Status", "") ?? "";

// ✅
var type = row.getString("En_Status", "");
```

### 2.4 SQL 安全

- **禁止**随意拼接 SQL 后运行。
- **禁止**用字符串拼接参数当作 SQL 运行。
- 将参数直接作为 mooSQL 参数时，非字段名一般无需考虑 SQL 注入（自动参数化执行）。
- 字段名等标识符需另行校验，不可当普通值参数偷懒拼接（`BizServiceBase.IsSafeSqlIdent` / 白名单枚举）。
- **允许完全无参数的固定 SQL** 直接 `exeQuery` / `exeNonQuery`：语句为**编译期常量**（字面量或 `const`/`static readonly` 常量），**不含** `$"..."` / `string.Format` / `+` 变量拼接 / 任何运行时入参。此类无注入面，可直接运行；能写 builder 时仍优先 builder。审计 P1a **不计**此类固定 SQL。
- **允许** `BatchSQL`（`useBatchSQL` → `newRow`/`addInsert`/`addUpdate` → `exeNonQuery()`）：链式设参后批量提交，**不属于**拼接 SQL 违规。
- **允许必要 DDL / 元数据探测** 使用静态或标识符白名单后的 `exeNonQuery`/`exeQuery`。**禁止**把用户输入直接拼进表名/列名。
- **允许必要批量 MERGE**：入参须 `Guid.TryParse` / 常量规则码等已校验；优先能拆则拆成 `doUpdate`/`doInsert`/`BatchSQL`。
- **禁止**在查询条件里对字符串列包 `LTRIM` / `RTRIM` / `UPPER` / `LOWER` 再比较。应**直接** `where("Col", val)`；入参可在 C# 侧 `Trim`。
- **禁止**把方言限行写进 `.select(...)`，如 `.select("TOP 1 Col")`。应使用 `.top(n)`（或 `skipTake(0, n)`）。
- **禁止**在 `where` / `whereFormat` 条件串里硬写 `ISNULL(col,v)=v`。应使用 `.whereIsOrNull(col, v)`。
- **禁止躲扫描**：不得为降低静态审计 Hits，把仍含运行时拼接的 SQL 先赋中间变量再 `.select(var)` / `.orderBy(var)`。
- **纯行数查询**用 `.count()` 得 `int`；**禁止**仅为取行数写 `.select("COUNT(*) as cnt")…query*`（GROUP BY / 相关子查询内 COUNT 除外）。正反例与 Demo 见 [SQL安全审计要求.md](../audit/SQL安全审计要求.md)。

```csharp
// ❌ 禁止
kit.select("*").from("T").where("Id='" + id + "'");
kit.where("UPPER(LTRIM(RTRIM(En_SourceUrl)))", url);
kit.exeNonQuery($"UPDATE T SET A='{name}' WHERE Id='{id}'");
kit.select("TOP 1 Sa_EbNoteOID").from("Sa_EbNote");
kit.where("ISNULL(SYS_Deleted,0)=0");
var sql = a + b; kit.select(sql);   // 躲扫描，同等禁止

// ✅ 参数交给 mooSQL；列直接比；限行用 top；可空相等用 whereIsOrNull
kit.select("*").from("T").where("Id", id);
kit.where("En_SourceUrl", url.Trim());
kit.top(1).select("Sa_EbNoteOID").from("Sa_EbNote").whereGuid("Sa_EbNoteOID", oid);
kit.whereIsOrNull("SYS_Deleted", 0);
kit.whereLike("mtb.En_Title", keyword);
kit.whereLikes(["mtb.En_Title", "mtb.En_Summary"], keyword);

// ✅ 完全无参数的固定 SQL（字面量，无插值/无拼接）可直接运行
const string EnsureColSql = @"
IF COL_LENGTH('Sa_Foo','Bar') IS NULL
  ALTER TABLE Sa_Foo ADD Bar nvarchar(50) NULL;";
kit.exeNonQuery(EnsureColSql);
```

### 2.5 SQLBuilder.set 赋值约定

- **`set` 接受 `DataRow` 索引值**：`kit.set("Col", row["Col"])` 时，mooSQL 已对 `DBNull` 及其它常见类型做适配；**一般不必**再写成 `row.getString(...)` / `Convert.ToXxx` / 手工判 `DBNull` 后再 `set`。
- **当前时间优先 C# 时钟**：设置「现在」用 `.set("Col", DateTime.Now)`。**禁止** `.set("Col", "getdate()", false)` / `"GETDATE()"`。
- **Guid / DateTime / 数值不要 `ToString()` 再 set**：如 `.set("SYS_LAST_UPD_BY", userId)`，禁止 `.set(..., userId.ToString())`（目标列非字符串时）。

```csharp
// ✅ set 直接吃 DataRow 单元格；时间用 DateTime.Now；Guid 原样传
kit.setTable("Sa_EbNote")
    .set("En_Title", row["En_Title"])
    .set("En_Cata_FK", row["En_Cata_FK"])
    .set("SYS_LAST_UPD", DateTime.Now)
    .set("SYS_LAST_UPD_BY", userId);

// ❌ 仅为塞进 set 再包一层强转 / ToString；❌ 当前时间写 getdate()
kit.set("En_Title", row.getString("En_Title", ""));
kit.set("SYS_LAST_UPD", "getdate()", false);
kit.set("SYS_LAST_UPD_BY", userId.ToString());
```

仅当需要把**表达式**写入 SQL（如 `"p.Po_Year"`、`"NEWID()"`）时，才用 `.set(col, expr, false)`。

### 2.6 禁止对数据量大的表做 Join

列表 / 导出 / Biz 查询体一旦挂上大表 Join 或相关子查询，**每一行**都会扫附属大表，会拖垮整页甚至所有复用该查询体的接口。展示用附属信息**不得**塞进主列表 SQL，应**前端按当前页再调接口**补数。

典型大表：明细/流水/日志/附件全文类事实表（随业务增长，不以本表为限）。

| 禁止 | 允许 |
|------|------|
| 列表主查询 `LEFT JOIN` / `INNER JOIN` 大表 | 本表字段（`FieldKind.Base`） |
| Row 上 `SooColumn(Kind = FieldKind.Join)` 里写相关子查询扫大表 | 主查询已按主键/外键收成**很小结果集**后，再按该键查附属表 |
| 把附属展示字段写进被多页复用的 `Biz_*Row`，让所有 `qlist` / 导出买单 | 列表先返回 OID / FK；前端对当前页去重后调专用接口，并按键缓存 |
| 「先能显示就 Join」的列表增强 | 点开或列表加载后再请求 |

```csharp
// ❌ 列表每行相关子查询扫大表明细
[SooColumn(Kind = FieldKind.Join, SrcField = "(select stuff((select … from BigDetail …", Alias = "detailNames")]
public string detailNames { get; set; }

// ✅ 列表只带本表外键；附属信息由前端按键调接口
[SooColumn(Name = "En_Cata_FK", Kind = FieldKind.Base)]
public Guid? En_Cata_FK { get; set; }
```

```javascript
// ✅ 当前页去重后调接口，按键缓存
await Promise.all(uniqueIds.map((id) => api.queryXxxForDisplay(id)));
```

已生成的小维表 Join（码表、名称维表、行数稳定且有主键）不在本条之列。拿不准时：**主列表不加 Join，附属信息走接口。**

## 3. 主键、外键参数强类型化

> **规范 3**：主键 / 外键在实体已声明为 `Guid?` 时，相关函数入参、局部变量与 SQL 传参应尽量使用 `Guid?`，避免长期以 `string` 传递 OID。

### 3.1 适用范围

| 类别 | 常见命名 | 说明 |
|------|----------|------|
| 主键 | `{表名}OID`（如 `Sa_EbNoteOID`、`Sa_EbCataOID`） | 表主键列 |
| 外键 | `{表名}_FK` 或业务约定 FK（如 `En_Cata_FK`、`Tm_TopicOID`） | 指向他表主键的列 |

**判定前提**：同表已有实体（**表名实体**，或 Biz 下的 `Biz_*Row`）将该列明确声明为 `Guid?`。若实体仍为 `string` / 其它类型，**不要**强行改成 `Guid?`；以实体声明为准。

### 3.2 要求

| 场景 | 做法 |
|------|------|
| 函数参数 / 返回值 | 涉及上述主键、外键时优先 `Guid?` |
| `DataRow` 读取 | 用 `row.getGuid("Sa_EbNoteOID")`；**禁止** `getString` 后再 `Guid.TryParse` 作为常规写法 |
| 有效性 | `oid.HasValue && oid.Value != Guid.Empty`（或项目统一扩展）；无效时早退或跳过 |
| SQLBuilder | **相等条件**用 `.whereGuid("Col", oid)`（见 [数据库查询.md](./数据库查询.md)）；`.set` / `setGuid` / `whereFormat` 直接传 `Guid?`；**禁止** `ToString()` 拼接或 `TRY_CONVERT` 拼 OID |
| HTTP / 前端入参 | API 边界可为 `string`；进入业务后立刻 `Guid.TryParse` → `Guid?`，后续链路保持强类型 |

### 3.3 例外（可保留 string）

- 目标列本身是**字符串**承载的 Guid 文本：比较/过滤时用 `oid.Value.ToString("D")`，并在处所注明原因。
- `DataTable.Select` 等仅接受表达式字符串的过滤：临时 `"D"` 字符串，不回流污染 SQL 参数类型。
- 非 OID 语义的编码字段（业务编码、层次码、证件号）：保持 `string`。

```csharp
// ❌ 实体已是 Guid?，仍全链路 string + 拼接
void Load(string noteOid) {
    kit.where("Sa_EbNoteOID='" + noteOid + "'");
}
var s = row.getString("En_Cata_FK", "");

// ✅ 强类型；读 getGuid；条件参数化
void Load(Guid? noteOid) {
    if (!noteOid.HasValue || noteOid.Value == Guid.Empty) return;
    kit.whereGuid("Sa_EbNoteOID", noteOid);
}
var cataFk = row.getGuid("En_Cata_FK");
```

历史代码触达时按本条收敛；**新增 / 改动路径一律按 `Guid?` 传递**（在实体已声明的前提下）。

## 4. 接口入参：专用 DTO 优先

> **规范 4**：Controller / API 入参优先**专用 DTO**；禁止用 `JObject` 承接后再手工 `para["key"]?.ToString()`。

### 4.1 适用范围

| 场景 | 做法 |
|------|------|
| 标准列表查询 | `[FromBody] BizQueryInput`（见 `SleveenAdmin.Foundation.Biz`） |
| 字段形状固定、可建模的入参 | 专用 DTO / 实体 |
| 保存 / 删除等 | `JsonElement` + 基类解析（`SaveCore` / `RemoveCore`），或专用 DTO |
| 动态简单键值袋（少量标量） | 可 `Dictionary<string, object?>` / 封装取值助手；**禁止** `JObject` 索引取值作为常规写法 |
| 深层嵌套 JSON 树、需 `JToken` 游走 | 可保留 `JObject`/`JToken`，并在处所注明原因 |
| 返回值 | 走 `ApiResult` / `Ok(...)`；本条约束的是**入参** |

### 4.2 取值约定

| 类型 | 建议 |
|------|------|
| 分页列表 | `BizQueryInput`：`Page`/`PageNum`/`PageSize`/`Keyword`/`Filters`/`OrderBy` |
| Guid | `Guid.TryParse` / `getGuid`（DataRow）/ `whereGuid` |
| 缺省值 | 方法第 2 参即为缺省（同 §2.3，勿再叠 `??`） |

```csharp
// ❌ 动态简单对象却用 JObject + 索引取值
public IActionResult Merge([FromBody] JObject para)
{
    var id = para["id"]?.ToString();
    ...
}

// ✅ 专用 DTO
public IActionResult QList([FromBody] BizQueryInput input) => QListCore(input);
```

### 4.3 纪律

- **新增 / 改动**路径：固定形状一律专用 DTO；标准列表用 `BizQueryInput`。
- 历史 `JObject` 入参：触达时改为 DTO 或强类型取值。
- **禁止**为省事继续写 `para["x"]?.ToString()` / `(string)para["x"]` 作为常规写法。

## 5. 禁用 dynamic

业务与基础设施代码中**禁止使用 `dynamic`**（含参数、局部变量、字段、返回值、属性）。

| 要求 | 说明 |
|------|------|
| 禁止声明 | 不得写 `dynamic kit`、`dynamic row`、`dynamic obj` 等 |
| 禁止传递放大 | 不得把静态类型值赋给 `dynamic`，也不得以 `dynamic` 参数调用本可静态签名的方法 |
| 替代 | 使用具体类型（如 `SQLBuilder`、`DataRow`、`DataTable`、实体、`BizQueryInput`、`JsonElement`、必要时 `JObject`/`JToken`、泛型） |

原因：`dynamic` 走运行期绑定，扩展方法（如 `DataRow.getString`）无法解析，且失去编译期检查，易在运行期才暴露错误。

```csharp
// ❌ 禁止
private void DoWork(dynamic kit) { ... }
dynamic row = dt.Rows[0];

// ✅
private void DoWork(SQLBuilder kit) { ... }
DataRow row = dt.Rows[0];
```

历史代码中已有 `dynamic` 的：触达时改为静态类型；**新增代码一律不得引入**。第三方互操作等极少数无法静态表达的场景须经人工确认后方可例外，并在处所注释原因。

## 6. 函数体量与业务拆分

### 6.1 体量

- 禁止巨型类或巨型函数。
- 一个函数一般不超过 **100 行**（配置、静态定义等除外）。
- 超长时拆私有方法或独立协作类。

### 6.2 核心逻辑独立建类

具有复杂逻辑的核心业务，应**独立建类**，不全部落入 `Biz*Service`。Service 负责编排与对外入口，细节由协作类承载。

```csharp
// ❌ 复杂流程全堆在 BizService
public class Biz_FooService {
    public void SaveAll(...) { /* 200+ 行校验、算费、写多表 */ }
}

// ✅ Service 编排，逻辑类承载细节
public class Biz_FooService {
    public void SaveAll(...) => new FooSaveLogic(...).Execute();
}
```

### 6.3 删除语义（逻辑 vs 物理）

> 审计分级与检查清单见 [审计要求.md](../audit/审计要求.md) §6。

| 类型 | 典型实现 |
|------|----------|
| **物理删除** | `doDelete` / `DELETE` / 实体 `Remove()` |
| **逻辑删除** | `SYS_Deleted` 置真后 `doUpdate`（`BizServiceBase.RemoveByOIDs` 默认逻辑删） |

- 需可恢复或仍被引用：**优先逻辑删除**，查询侧 `whereIsOrNull("SYS_Deleted", 0)`。
- 物理删除须注释原因；同表双路径须参数/方法名区分。
- 空「逻辑删除」region 或「注释软、实现硬」一律按**物理**计。

## 7. 覆盖区

> 权威细则见 [代码生成规范与融合.md](./代码生成规范与融合.md) **§3.2–§3.4**（按产物类型能否改、破坏标记写法）。本节为速查摘要。

### 7.1 原则（速查）

| 对象 | 要求 |
|------|------|
| Entity / Biz Service / Row | **一律禁止**污染覆盖区 |
| VC / Page 等 | 须改区内时：打 `[cover-break] [已改]`，或整段删除该覆盖区 |

### 7.2 破坏标记（速查）

- 未破坏：`[autoGenerate] [cover] [勿改]`
- 已破坏：`[autoGenerate] [cover-break] [已改]`（起止 region 成对）
- 前端 `// #region` 同样适用；禁止只改内容、不改标记。

## 8. 前端 UI 分层与落位

> 适用 `web/`。选择器细则另见 [选择器设计规范.md](./选择器设计规范.md)。

按「是否含业务 / 是否可跨子项目复用」落位，禁止把业务逻辑塞进纯 UI。

| 层级 | 路径 | 定位 | 允许 | 禁止 |
|------|------|------|------|------|
| 纯 UI | `web/src/ui/` | 通用控件与布局壳 | 展示、交互、插槽、极少接口（仅控件自身所需） | 特定业务字段、流程、领域校验 |
| 扩展 UI | `web/src/uiext/` | 面向平台能力的扩展组件 | 代码生成、运行时装配等基础设施 | 某一业务子系统的专属逻辑 |
| 子项目个性化 UI | `web/src/widgets/<子项目>/ui/` 或 `src/ui/` | 该业务系统的个性化界面件 | 视觉与交互定制、子项目内复用 | 升格为全站纯 UI 却仍绑死业务 |
| 子项目扩展 UI | `web/src/widgets/<子项目>/uiext/` | 有业务耦合、但仍抽象为独立组件 | 选择器、业务表单片段等可复用件 | 仅某一页面用的一次性拼装（应留在 views） |

### 8.1 `src/ui/`：纯 UI 控件

- **定位**：纯 UI，与特定业务逻辑解耦。
- **接口**：无调用，或仅有控件自身必需的极少接口；不得承载业务 API 编排。
- **扩充原则**：业务侧需要更强能力时，只从**扩充控件能力**（props / slots / 事件 / 可配置行为）入手，**杜绝业务侧逻辑渗入**。

### 8.2 `src/uiext/`：扩展 UI（含代码生成基座）

- **定位**：扩展 UI 组件，服务平台与生成体系，而非某一业务域。
- **当前主要子目录**：`web/src/uiext/gene/` —— 代码生成所依赖的基础组件（如 live VC/Page、panel、vcbase、生成相关 hook/utils）。
- 新增生成期/运行时通用能力优先落在 `uiext/gene`（或同级按能力再分目录），勿与 `widgets` 业务组件混放。

### 8.3 `widgets/<子项目>/…/ui/`：业务个性化 UI

- 业务系统的**个性化** UI 组件放在对应子项目（如 `widgets/officeman`、`widgets/sysext`）。
- 仅该子系统需要的样式、元素、局部面板放此处；不要反向塞进 `web/src/ui/`。

### 8.4 `widgets/<子项目>/uiext/`：业务耦合但可抽象的独立组件

- 仍有业务耦合，但需要抽成**独立可复用组件**时，放在子项目的 `uiext` 下。
- 典型如各类选择器：`widgets/<子项目>/uiext/selector/`。
- 与纯 UI 的边界：基座（无业务）在 `src/ui`；字段映射、onload、挂 Biz 页等在 `widgets/.../uiext`。

落位速查：

```
是否特定业务？
  ├─ 否 → web/src/ui/ 或 web/src/uiext/（平台/生成能力 → uiext，尤其 gene）
  └─ 是 → 是否需抽象为独立、可复用组件？
        ├─ 是（选择器等） → widgets/<子项目>/uiext/
        └─ 否（单页拼装） → widgets/<子项目>/views/...
        个性化控件（非独立业务抽象） → widgets/<子项目>/ui/
```
