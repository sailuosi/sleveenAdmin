# 树查询

> **状态**：专项代码规范（指导 Biz `qtree` / Service `loadTreeList` 的日常开发与改造）  
> **目录**：`doc/pc/design/`  
> **相关实现**：mooSQL `TreeSQLBuilder` / `TreeListOutput<T>`（`mooSQL2024/pure/src/adoext/tree/`）；仓储侧可用 `SooRepository.GetTreeList`。  
> **相关**：SQLBuilder 条件类型化见 [数据库查询.md](./数据库查询.md)（Guid 用 `whereGuid` 等）；模块范式见 [biz-module-paradigm.md](./biz-module-paradigm.md)。

---

## 1. 范围

| 部分 | 说明 |
|------|------|
| 入参 | 树查询 DTO（`pk` / `deep` / 可选 conditions）→ 转成构建参数 |
| 构建 | mooSQL `TreeSQLBuilder` 或仓储 `GetTreeList` |
| 出参 | `TreeListOutput<T>`，**T 为强类型实体**（DBLayer 表实体） |
| 路由 | Biz Controller 上 `*/qtree`（如 `ebook/ebcata/qtree`） |

适用路径：`backend/**/*.cs`（Biz Service、Biz Controller）。前端树 VC 消费 `Nodes[].Record` 字段名与实体属性一致即可，本文不约束前端。

本仓当前 ebook 分类等列表以扁平 `qlist` 为主；**新增树接口**按本规范落地。

---

## 2. 实现路径（强类型标准链路）

```text
HTTP POST …/qtree
  └─ Controller: [FromBody] 树查询 DTO
       ├─ 转为构建参数（deep / pk / BuildingSQL）
       ├─ 可选 OnBuildSQL(kit => …)   // 仅本接口附加条件
       └─ Service.loadTreeList(para)
            └─ TreeSQLBuilder / useTree
                 .selectPKFK(主键列, 父FK列)
                 .setDeep(deep).setPK(pk)
                 .OnFilterRoot(…)          // 根节点：父FK 为空
                 .OnQueryBase(kit => {
                      // select + from
                      // 软删 / 排序等公共条件
                      // BuildingSQL?.(kit)
                 })
                 .GetTreeList<TEntity>() / loadTreeList<TEntity>()
            → TreeListOutput<TEntity>
```

**返回形态**（mooSQL `TreeListOutput<T>`）：

- `Nodes`：根层节点列表  
- 每个节点：`Record`（`T`）、`Children`、`Level`、`PKValue` / `FKValue`

## 3. 强类型约定

### 3.1 实体选型

| 选用 | 说明 |
|------|------|
| **优先** DBLayer 表实体（如 `Sa_EbCata`） | `GetTreeList<T>()` / `loadTreeList<T>()` 按列名映射 |
| 一般不选 `Biz_*Row` | Row 多用于分页列表 / 保存；树查询用表实体即可 |
| **禁止** `JObject` / 行转 JSON 弱类型 | 历史写法；新增与触达改造一律强类型 |

### 3.2 Service：`loadTreeList`（示意）

以 ebook 分类树为例（父 FK 按实体实际字段调整）：

```csharp
public TreeListOutput<Sa_EbCata> loadTreeList(/* TreeQueryPara */ para)
{
    var kit = Db.useSQL(); // 或项目封装的 useTree
    // 使用 mooSQL TreeSQLBuilder：
    // selectPKFK("Sa_EbCataOID", "Ec_Parent_FK")
    // OnFilterRoot: whereIsOrNull("Ec_Parent_FK", Guid.Empty)
    // OnQueryBase: select/from + whereIsOrNull("SYS_Deleted", 0) + BuildingSQL
    // 结束：loadTreeList / GetTreeList<Sa_EbCata>()
}
```

要点：

- 根节点过滤用 **`whereIsOrNull(父FK, Guid.Empty)`**，禁止手写 `is null or = '0000…'` 字符串。
- 结束用 **强类型** `TreeListOutput<TEntity>`，不要 `Func<DataRow, JObject>`。
- 选出的列须覆盖实体映射所需字段（含 PK / 父 FK）。

### 3.3 Controller：`qtree`

```csharp
[HttpPost("ebook/ebcata/qtree")]
public TreeListOutput<Sa_EbCata> QueryCataTree([FromBody] /* TreeQueryDto */ input)
{
    // var para = input.ToQueryPara();
    // 可选：para.OnBuildSQL(kit => kit.where("Ec_Active", true));
    return _service.loadTreeList(para);
}
```

要点：

- 返回类型与 Service 一致：`TreeListOutput<TEntity>`。
- 路由挂在 `biz/{slug}/` 下，与 PageApi 一致。
- 权限 / 系统位过滤在 Service `OnQueryBase` 或 Controller 附加钩子中完成。

## 4. 入参约定

| 字段 | 含义 |
|------|------|
| `pk` | 懒加载父节点主键；空则查根 |
| `deep` | 展开深度；未传时建议默认 `2` |
| `conditions` / `orderBy` | 动态条件与排序（按平台约定） |
| 扩展袋 | 如 `includeDisabled`；Service 侧按需读取 |

Controller 侧附加固定条件优先 `OnBuildSQL` / `BuildingSQL`，再进入树构建。

---

## 5. 权限根过滤（可选）

需要按职责 / 组织范围裁根时，用独立的「权限根」钩子（若封装提供 `OnFilterAuthRoot`），**不要**把范围条件误塞进「无父即根」的 `OnFilterRoot`。

```csharp
.OnFilterRoot(kit => kit.whereIsOrNull("Ec_Parent_FK", Guid.Empty))
.OnFilterAuthRoot(kit => { /* 权限根范围 */ })
```

## 6. 反例与触达改造

```csharp
// ❌ 弱类型
public TreeListOutput<JObject> loadTreeList(...) {
    …
    .GetTreeList(row => /* RowToJobj */);
}

// ❌ 根过滤手写空 GUID 字符串
kit.where("(Parent_FK is null or Parent_FK='00000000-0000-0000-0000-000000000000')");

// ✅ 见 §3.2 / §3.3
```

**历史弱类型树**：新增一律强类型；维护触达（改条件、改路由、抽公共）时一并改为 `TreeListOutput<TEntity>`。
